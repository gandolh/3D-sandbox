# Material slugs are never checked against verified.json

`asset-resolves` checks placements and scatter assets only
(`packages/schema/src/lint/rules/references.ts`). A material's
`<source>/<slug>` is never checked against anything, and
`assets/verified.json`'s `materials` list is generated by
`npm run assets` but read by nothing — `scenes/build.ts` only reads
`verified.assets`.

So the layer `download-list.ts` describes as "the layer that stops invented
slugs" does not cover materials at all. An invented material slug builds clean
and silently renders as its `baseColor` fallback.

## How it surfaced

During brief 62 (2026-10-01), `npm run assets` was rerun. The committed
`verified.json`, `DOWNLOADS.md` and `download.sh` were missing
`ambientcg/PavingStones137`, which `greenhollow` uses. They had not been
regenerated since that material was added, and no check noticed, because
nothing compares material slugs with the verified list. The regenerated files
are now correct (18 assets, 187.8 MB), but nothing stops the same drift again.

## Shape of a fix

Probably: have `asset-resolves` (or a sibling rule) check material slugs against
a `knownMaterials` option, and pass `verified.materials` plus the downloaded
manifest from `scenes/build.ts`, the same way assets are passed. The
`procedural` source has no slug and is exempt.
